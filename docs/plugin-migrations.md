# Plugin migrations

A plugin with tables has a migration stream of its own: the migrations in its assembly that name `PluginDbContext<TPlugin>` in `[DbContext]`, with the history table `cms_{plugin}__migrations` ([ADR 0003](decisions/0003-plugin-contribution-contracts.md)). Until [#2711](https://github.com/fluentcms/FluentCMS/issues/2711), a plugin holds the SQLite set only.

## The design-time factory

`PluginDbContext<TPlugin>` is generic, and a plugin references neither Core nor a data provider, so `dotnet ef` cannot build the context from the plugin's project. A startup project that references the plugin and the SQLite provider holds a design-time factory for the closed type, which builds the context as a host does with `PluginDbContextDesignTime.Create`. For the webhooks plugin that is the test project:

```csharp
public sealed class WebhooksDbContextFactory : IDesignTimeDbContextFactory<PluginDbContext<WebhooksPlugin>>
{
    public PluginDbContext<WebhooksPlugin> CreateDbContext(string[] args) =>
        PluginDbContextDesignTime.Create<WebhooksPlugin>(new SqliteDataProvider("Data Source=:memory:"), new WebhookModel());
}
```

The factory names every model contributor the plugin adds. It never opens the database. The startup project references `Microsoft.EntityFrameworkCore.Design` with `PrivateAssets` set to `all`.

## Adding a migration

You need the `dotnet-ef` tool (`dotnet tool install --global dotnet-ef`).

1. Change the plugin's model contributor.

2. Scaffold the migration into the plugin's project, with the factory's project as the startup project:

   ```bash
   dotnet ef migrations add AddWebhookFilters --project src/plugins/FluentCMS.Plugins.Webhooks --startup-project tests/FluentCMS.Plugins.Webhooks.Tests --output-dir Migrations
   ```

3. Add `// <auto-generated />` as the first line of the new migration file, as for the [system migrations](system-migrations.md).

4. Run the plugin's tests. A model ahead of its migrations stops the host with EF's pending model changes error, and the webhooks tests also check that the snapshot matches the model.

Do not edit a migration that has shipped.
