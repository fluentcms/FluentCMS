The second preview of the FluentCMS backend. These notes collect the changes since `1.0.0-preview.1` as they land.

## Changes that break code built before this preview

- A search matches only the searchable fields the caller may read (#3263). The search plugin keeps a row for each searchable field of an entry, so the column `field` of `cms_search_entry` went into the search plugin's `Initial`, since a preview upgrades no database. A database made by `1.0.0-preview.1` lacks that column and is refused with `FCMS1308`, at start and by `fluentcms migrate`, with nothing applied; recreate it and rebuild the index (`POST /api/management/v1/search/rebuild`).
- `ISearchIndex.MatchesByField` is a new member, with a default of `false`, and `SearchRequest.Fields` names the searchable fields the caller may read, or is `null` when it may read them all. An index other than the search plugin's is refused `q` with `FCMS2211` for a caller who may not read every searchable field, until it matches only the fields of `SearchRequest.Fields` and returns `true` (#3263).
- `SystemOperation.Begin` takes the host's `TimeProvider` after the accessor, as `SystemOperation.Begin(accessor, time, Origin.Job, site)`, and stamps the operation with it (#3310). An event read before it is published, with no source set, has the system's source at `DateTimeOffset.MinValue`; the bus stamps it when it is published, as before.
- The clients, `FluentCMS.Client` and `@fluentcms/client`, throw a problem for an empty answer, a 204 or a literal `null` where a call returns a result, which they answered as null or `undefined` before (#3310), and refuse the path segments `.` and `..` (#3273). The calls of `@fluentcms/client` are `async`, so an empty, `.` or `..` segment rejects the promise they return, where it threw before the call returned.
- A usage row of the AI assist plugin keeps the name its principal had at the call (#3418), so the column `principal_name` of `cms_ai_usage` went into the plugin's `Initial`, since a preview upgrades no database. A database made by `1.0.0-preview.1` lacks that column and is refused with `FCMS1308`, at start and by `fluentcms migrate`, with nothing applied; recreate it, which starts the usage log, and with it the day's budget count, afresh.
- The MCP tool `schedule` with `action: unpublish` runs after a dry run, as `unpublish` does: a call answers the plan with a `confirmationToken` and schedules nothing, and the same call with `dryRun: false` and that token schedules it. A scheduled publish runs at once as before, and refuses `dryRun` and `confirmationToken` (#3361).
- A user keeps at most `maxConsentsPerUser` (20, a new key of the settings area `mcp`, and `McpClientRegistrationPolicy.MaxConsentsPerUser`) MCP clients that the `open` policy approved by consenting, and a client counts while it is there, also after its consent was ended. A consent that would keep one more is refused on the hosted error page and logged with event 9008 (#3397).
- `IMcpClients.RemoveOpenApprovedAsync` is a new member with no default, which an implementation other than core's must add (#3397).

## Additions

- `@fluentcms/client` takes a `signal` in the last options argument of every call (`RequestOptions`, which `WriteOptions` extends) and a `timeoutMs` in `ClientOptions`, which abort the request and the read of its answer (#3310).
- `FluentCmsProblem.retryAfter` (seconds) and `FluentCmsProblemException.RetryAfter` (`TimeSpan?`) hold the server's `Retry-After` (#3310). In a browser a date-form `Retry-After` cannot be read from another origin, since `Date` is not an exposed header; the API sends seconds.
- `IMediaService.RequireUpdateAsync(id)` checks that the caller may change an asset's metadata, as `UpdateAsync` checks it, and writes nothing; its default refuses with `NotSupportedException`, so an implementation other than the media plugin's builds as before (#3418).
- `POST /api/management/v1/ai/actions/altText` runs for an asset alone, with `options.mediaId` and no `type` and `field`, for a caller who may update the asset as `PATCH /media/{id}` checks it; it only suggests and never writes the asset (#3418).
- `GET /api/management/v1/ai/fields` answers `assets`, whether the caller may ask for the alt text of an asset alone (#3418).
- `GET /api/management/v1/ai/usage` answers `principalName` on each row, the name the principal had at the call, for a caller who holds `ai.usage.read` alone (#3418).
- `GET /api/management/v1/ai/usage` answers `totals.groups`, the calls and tokens of the filter for each principal, by kind and id, and action (#3418).
- `GET /api/management/v1/permissions/row-rules` lists the registered row rules that a grant's `rowRule` may name, each with the content types it is registered for (`typeNames`, null for every type), for the callers who may read `GET /permissions` (#3417).
- `POST /api/management/v1/mcp/clients/remove` with `{ "registeredFrom", "registeredBefore" }` removes the MCP clients the `open` policy approved that registered in that span, 100 in a call, with `mcp.manage` for the instance, and answers `{ "removed", "more" }`. A call that names neither time, a time without an offset or an empty span is refused with the new code `FCMS1610`, and a client the database refuses to delete is logged with event 9009 (#3397).
- `PUT /api/management/v1/mcp/clients/{id}/role` with the role a client has records the caller as `approvedBy` on a client the `open` policy approved, so that the cleanup and the bulk removal keep it (#3399).
- `ValidationContext.Fields` lists the fields a validation run validates, at any depth, as `ValidatedField` records of the field, its path and its value, so that a validator reads once for all of them; it is empty for a context made with the constructor (#3349).
