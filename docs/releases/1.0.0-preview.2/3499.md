## Additions

- `SettingsAttribute.InstanceOnly` marks a settings area whose code reads the instance defaults only, with `ISettings<T>.GetDefaultAsync`: `[Settings("area", InstanceOnly = true)]`. `branding` and the MCP plugin's `mcp` are marked so. Each area of `GET /api/management/v1/settings` says it as `instanceOnly`, for a plugin's area as for core's, so that a client sends such an area to `/settings/{area}/defaults` without knowing it by name. The flag only describes the area in that list and changes nothing about how the area is read or written. A site write to such an area through `PUT /settings/{area}` is still accepted and stored, and has no effect only because the area's code reads the defaults; `ISettings<T>.GetAsync(site)` still gives the site's values, so the flag is true only when the area's own code reads with `GetDefaultAsync` (#3499).
