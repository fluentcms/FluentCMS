## Changes that break code built before this preview

- The `width` and `height` of an image are those it is shown at, after its EXIF orientation, as `IImageProcessor.IdentifyAsync` reads them, so a photo stored turned answers them the other way round from before; the job `media.dimensions.backfill` corrects the JPEG, WebP and AVIF images stored before, whose type the processor reads, once per database, without changing their version or raising an event (#3309).
- An SVG uploaded, replaced or imported with `Svg` set to `sanitize` keeps only the SVG elements and attributes of drawing the plugin lists, and loses every link and `url()` that is not to a `#fragment` of the file, embedded `data:` images included (#3309). SVGs stored before are not sanitised again: they are safe where the CMS serves them with its `Content-Security-Policy`, not where a page inlines them or a CDN drops the header. An import line that names the storage key of such an older SVG is refused with `FCMS3220` (`TransferFileMissing`), since sanitising it now changes its checksum.

## Additions

- The media plugin logs a run of `media.dimensions.backfill` with event 9275, an image whose file it cannot read with 9276, and a start that cannot start the check with 9277 (#3309).
