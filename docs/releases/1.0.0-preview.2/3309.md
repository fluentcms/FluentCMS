## Changes that break code built before this preview

- The `width` and `height` of an image are those it is shown at, after its EXIF orientation, as `IImageProcessor.IdentifyAsync` reads them, so a photo stored turned answers them the other way round from before; the job `media.dimensions.backfill` corrects the JPEG, WebP and AVIF images stored before, whose type the processor reads, once per database, without changing their version or raising an event (#3309). To run the check again, delete the row with id 2 of `cms_media_signing_key` (`DELETE FROM cms_media_signing_key WHERE id = 2`) and start an instance. An image uploaded by an instance of an earlier version during a rolling upgrade can keep the size of its header after the check is done; running the check again corrects it.
- An SVG uploaded, replaced or imported with `Svg` set to `sanitize` keeps only the SVG elements and attributes of drawing the plugin lists, and loses every link and `url()` that is not to a `#fragment` of the file, embedded `data:` images included (#3309). A value read as CSS that holds anything removed goes whole, so one `url(data:…)` or an `@font-face` whose `src` is a `url(…)` removes the whole `<style>` element or `style` attribute; a `<style>` that stays applies to the whole page when a page inlines the SVG. SVGs stored before are not sanitised again: they are safe where the CMS serves them with its `Content-Security-Policy`, not where a page inlines them or a CDN drops the header. An import line that names the storage key of such an older SVG is refused with `FCMS3220` (`TransferFileMissing`), since sanitising it now changes its checksum.

## Additions

- The media plugin logs a run of `media.dimensions.backfill` with event 9275, an image whose file it cannot read with 9276, and a start that cannot start the check with 9277 (#3309).
