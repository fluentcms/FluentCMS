## Changes that break code built before this preview

- The jobs of the first-party plugins that had no attempt timeout have one, whatever `FluentCms:Jobs:AttemptTimeout` says: `mcp.client-cleanup` and `webhooks.deliver` 10 minutes, `webhooks.queue` 5 minutes, `media.dimensions.backfill` 30 minutes and `media.variants.cleanup` an hour (#3529). Past it the job's token is cancelled and the attempt fails with `FCMS2508` and is retried, and a job that ignores its token is abandoned 30 seconds later and its worker freed. `webhooks.deliver` has the time of the longest send timeout the options allow, five minutes, and more, so no send is cut off.
- `media.variants.cleanup` is resumable: a run stopped at its limit has succeeded, and the next day's run goes on with the variants and assets that are left, where a long backlog would have been failed and retried (#3529).

## Additions

- `JobsBuilder.AddJob<TJob, TPayload>(type, attemptTimeout, resumable)` is public, so a host registers a resumable job with `cms.Jobs.AddJob<TJob, TPayload>(type, attemptTimeout, resumable: true)`, as a plugin does through `IPluginServiceBuilder`. Such a job stops on its token wherever it is with what it did kept, and something runs it again, such as a schedule, since a run stopped at its limit has succeeded and is not retried (#3529).
