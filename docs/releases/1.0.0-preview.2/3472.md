## Changes that break code built before this preview

- An import line without a file whose storage key is in the folder of an asset of the instance is refused with `FCMS3220` (`TransferFileMissing`), in a dry run too, when that asset is deleted or no longer has that key as its file or a variant's, since the daily cleanup deletes such a file once nothing else names it. Such a line is also refused when that asset changes between the check of the file and the save of the line, as when it is deleted and purged meanwhile; import the package again, or export it with `mediaFiles=true` (#3472).

## Additions

- A replace, through `POST /media/{id}/replace` or by an import, of an asset whose old file or variant another asset of the library names leaves those files to a deleted row of their own, which the daily cleanup purges with them once no other asset names them: variant files at the next run, the original after `DeletedRetention`. They stayed before with no row that owned them, and were never deleted (#3472).
- The variant files that an asset on another asset's key made go to that asset when the first is deleted, or its site is, and are deleted with that asset's own. The variant row of an asset whose row is gone deletes its file only when the file is in that asset's own folder (#3472).
- A storage that instances share is safe only when they share the database too: an instance that purges, replaces or removes a site deletes the files it wrote even when an asset that another instance imported by a line without a file names them. Import between such instances with `mediaFiles=true` (#3472).
