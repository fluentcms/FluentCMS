## Changes that break code built before this preview

- An import line without a file whose storage key is in the folder of an asset of the instance is refused with `FCMS3220` (`TransferFileMissing`), in a dry run too, when that asset is deleted or no longer has that key as its file or a variant's, since the daily cleanup deletes such a file once nothing else names it. Such a line is also refused when that asset changes between the check of the file and the save of the line, as when it is deleted and purged meanwhile; import the package again, or export it with `mediaFiles=true` (#3472).
- An import line for an asset itself, without a file, that names a key in the asset's own folder which the asset no longer names, such as the file a replace left to a holder, is refused with `FCMS3220`, as a line whose file is not there (#3472).
- A limit, which this preview states: a storage that instances share is safe only when they share the database too. An instance that purges, replaces or removes a site deletes the files it wrote even when an asset that another instance imported by a line without a file names them. Import between such instances with `mediaFiles=true` (#3472).

## Additions

- A replace, through `POST /media/{id}/replace` or by an import, of an asset whose old file or variant another asset of the library names leaves those files to a deleted row of their own, which the daily cleanup purges with them once no other asset names them: variant files at the next run, the original after `DeletedRetention`. They stayed before with no row that owned them, and were never deleted. The replace checks again just before it deletes the old files, so a line of an import that names one of them meanwhile keeps it too. When that row cannot be saved, the files stay with no row that owns them, and the new warning 9278 says so and that they must not be removed by hand while an asset names them (#3472).
- The variant files that an asset on another asset's key made go to that asset when the first is deleted, replaced, or its site is deleted, and are deleted with that asset's own. Each goes on its own. One whose hand-over fails stays with a deleted asset for the next cleanup; after a replace its row is gone already, so its file stays with no row (#3472).
- The variant row of an asset whose row is gone deletes its file only when the file is in that asset's own folder (#3472).
