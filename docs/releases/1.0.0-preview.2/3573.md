## Changes that break code built before this preview

- A write that waits longer than `FluentCms:Content:LockTimeout` (10 seconds, at most a day, a new option) for what another write holds, the rows of its entry or on SQLite the database, gives up and answers 503 with the new code `FCMS2411` (`Entry busy`) and `Retry-After: 1`, with nothing of it stored. It waited until its command timeout (30 seconds by default) and answered 500 `FCMS3199`. A bulk reports such an item with `FCMS2411`, an import reports the item, a scheduled publish or unpublish is tried again, and GraphQL and MCP describe it as `FCMS2411` with status 503. A deadlock victim is run again as before (#3573).
- `IDataProvider.BeginWriteAsync` and `IDataProvider.IsLockTimeout` are new members with defaults: a provider other than the three of FluentCMS sets no lock timeout and its writes wait until their command timeout, as before (#3573).

## Additions

- The lock timeout of a write is set for its transaction alone: `SET LOCAL lock_timeout` on PostgreSQL, `SET LOCK_TIMEOUT` on SQL Server, set back before the transaction ends so that no connection keeps it, and the busy wait of the transaction's `BEGIN IMMEDIATE` on SQLite. A write sends one statement more on PostgreSQL and two more on SQL Server (#3573).
