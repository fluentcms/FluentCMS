## Changes that break code built before this preview

- The bulk removal of MCP clients and the cleanup job `mcp.client-cleanup` skip a client only when its delete crossed a consent or a token that arrived meanwhile, and log it with event 9009 as before: a refusal of a foreign key, or what the provider calls a deadlock (`IDataProvider.IsDeadlock`), as SQL Server may answer the same race under the store's serializable transaction. Any other failure of the save, such as a write of the outbox the database refuses, ends the bulk removal with a 500, and the clients removed before it stay removed, each with its activity row. Such a failure was taken for a consent that arrived, so one that lasted answered `{ "removed": 0, "more": false }`. A serialization failure of PostgreSQL (`40001`) has no member of the providers to tell it, so it is thrown too (#3448).
- The cleanup takes its clients in the order of their ids, and a client whose delete fails otherwise is logged with its id (event 9013, `OidcClientDeleteFailed`) and passed over, so that one client that cannot be deleted does not keep the run from the others; the run then fails with that failure, several in an `AggregateException`, and the job runner tries again (#3448).
- `IDataProvider.IsForeignKeyViolation` is a new member, with a default of `false`, so that a provider other than the three of FluentCMS has every failure of those deletes thrown. SQLite tells a foreign key by its extended code 787 and PostgreSQL by `23503`. SQL Server answers 547 for a check constraint too, so a foreign key is told by 547 with the constraint the message quotes named `FK_`, as EF names every foreign key of the model, or with the words `REFERENCE` or `FOREIGN KEY` in the message; a refusal whose message has neither, as a server may word it, is thrown, and the client is tried again at the next run or call (#3448).

## Additions

- `POST /api/management/v1/mcp/clients/remove` reads again, each in a transaction of its own, only the clients it would remove: those the `open` policy approved, found in SQL, that registered in its span, found in the state the same query reads. It opened a transaction for every client no administrator acted on, those outside the span and the pending ones included (#3448).
