## Changes that break code built before this preview

- The bulk removal of MCP clients and the cleanup job `mcp.client-cleanup` skip a client only when a foreign key refuses its delete, as it does when a consent or a token arrives meanwhile, and log it with event 9009 as before. Any other failure of the save, such as a write of the outbox the database refuses, ends the call with a 500 or the run with the error, which the job runner tries again; the clients removed before stay removed, each with its activity row. Such a failure was taken for a consent that arrived, so one that lasted answered `{ "removed": 0, "more": false }` (#3448).
- `IDataProvider.IsForeignKeyViolation` is a new member, with a default of `false`, so that a provider other than the three of FluentCMS has every failure of those deletes thrown (#3448).

## Additions

- `POST /api/management/v1/mcp/clients/remove` reads again, each in a transaction of its own, only the clients it would remove: those the `open` policy approved, found in SQL, that registered in its span, found in the state the same query reads. It opened a transaction for every client no administrator acted on, those outside the span and the pending ones included (#3448).
