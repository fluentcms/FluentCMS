## Changes that break code built before this preview

- While a publish, a discard, an unpublish, a scheduled publish or unpublish, or an import of an entry runs, its hooks included, a write to any locale of that entry waits for it to commit: these hold every locale row of the entry. A write of another locale did not wait for a publish before. No lock timeout is set, so a write that waits longer than its command timeout (30 seconds by default) fails with the database's timeout error, answered as an unexpected failure (500, `FCMS3199`), and is not run again (#3524).
- A discard whose locale was published, unpublished or given another status by another request between the discard's read and its holds answers 412 (`FCMS3105`) with the version it read; it went on with what it had read (#3524).
- A publish whose entry another request put in the trash while it ran answers 404 (`FCMS3104`), as a publish of an entry in the trash does. It answered 409 `FCMS2405` (`A hook changed the draft being published.`) on the previous build of this preview and 412 before (#3524).

## Additions

- Writes, publishes, unpublishes, schedules, scheduled jobs, imports, trash, restore and purge of one entry take its rows in one order, its `cms_document` rows first, each by its primary key and ordinal by locale code, so two of them that cross wait for each other. On PostgreSQL and SQL Server a publish of one locale and a shared write through another, a scheduled job and a write that ends its schedule, or an import and a shared write could deadlock, and one of them ran again after about one second on PostgreSQL and five on SQL Server (#3524).
- A save and a version restore decide their own status from what is stored once their swap holds the row, so a publish or an unpublish of that locale, or another locale's publish of the shared row, that committed between the write's read and its swap no longer leaves a stale status, such as `Modified` for a draft equal to what is published, `Draft` for a locale published or published and unpublished meanwhile, or `Modified` for one unpublished meanwhile (#3524).
- An unpublish decides whether it removes the shared published row under the holds of every locale row, so a publish or an unpublish of another locale that commits meanwhile no longer leaves a published locale without its shared row, or a shared row that no published locale uses (#3524).
- A trash, a restore or a purge of an entry to which a locale was added meanwhile runs again with that locale, so its hooks, checks and `EntryTrashedEvent` cover it (#3524).
