## Changes that break code built before this preview

- A multiple field or blocks that declares no maximum holds at most `MaxItems` items (1,000, the new option `FluentCms:Content:MaxItems`), and a value with more is refused with `FCMS2103`, through the SDK and an import too; a declared maximum, higher or lower, holds instead (#3307).
- A content hook runs for at most `FluentCms:Content:HookTimeout` (30 seconds, at most a day, a new option), and starts on the thread pool, so one that blocks before its first await is held to it too: one that runs longer has its token cancelled, and the write fails with the new code `FCMS2410` (503), naming the hook, and rolls back, to its savepoint inside another transaction, with what it tracked detached; it is logged with event 9406. A hook that timed out, or that had not ended when its caller was cancelled (a client that went away, a lost `Idempotency-Key`), may still be running, so its scope then writes and commits nothing more: further writes, a write around a nested one whose failure was caught, a commit of the caller's own transaction, and any save, `ExecuteUpdate`, `ExecuteDelete` or `ExecuteSql` on that scope's `CmsDbContext` are refused with `FCMS2410`, and a bulk reports the items after it as `NotRun`. A plugin's own context and other scopes are not covered. A hook that ends after `FluentCms:Content:SlowHookThreshold` (1 second) is logged with event 9407. A scheduled publish or unpublish whose hook timed out is tried again (#3307).
- A request with an `Idempotency-Key` that a repeat took over, after the renewals of its lease failed for a whole lease, is cancelled: what it had not committed rolls back, it answers `FCMS3142` (409), and event 9145 is logged (#3307).
- A line of a transfer package that names a locale for an entry of a type that is not localized is reported as an invalid item (`FCMS3212`) instead of an unexpected failure (`FCMS3215`) (#3305).
- A write that adds an entry to a site, or a locale of an entry, is refused with `FCMS2301` once the site is gone, also on an instance whose cache still has it, and a site deletion waits for such a write that is under way. `SiteDeletedEvent` is recorded in the outbox in the transaction of the deletion, so a cleanup of a plugin runs even when the process stops right after it, and a deletion whose event cannot be recorded does not happen (#3306).
- `IDataProvider.BeginSnapshotAsync` and `IDataProvider.LockSiteAsync` are new members with defaults: a provider other than the three of FluentCMS reads an export without a snapshot, and one whose database has more than one writer must lock the row of `cms_site` (#3305, #3306).

## Additions

- `POST /api/management/v1/transfer/import` takes `authors=keep|importer`, and `fluentcms import` takes `--authors keep|importer`: `importer` records the caller as the creator of the entries the import creates and as the updater of what it writes, where `keep`, the default, keeps the authors of the package (#3305).
- An export reads the entries of every type from one snapshot, so a save during it changes nothing in the package: a `REPEATABLE READ` transaction on PostgreSQL, a deferred transaction in WAL mode on SQLite, and `SNAPSHOT` isolation on SQL Server. No migration allows `SNAPSHOT` isolation, so a default SQL Server database exports without a snapshot, as before, and logs event 9189; an administrator turns it on with `ALTER DATABASE CURRENT SET ALLOW_SNAPSHOT_ISOLATION ON`, which needs `ALTER` on the database but not the database to itself. An export reads a batch of 100 entries in four queries (#3305).
- The lease of an `Idempotency-Key` is renewed every third of `InProgressTimeout` while its request runs, so a request that runs longer is not taken over; a renewal that fails is logged with event 9144 and tried again (#3307).
