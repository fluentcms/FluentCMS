## Changes that break code built before this preview

- A multiple field or blocks that declares no maximum holds at most `MaxItems` items (1,000, the new option `FluentCms:Content:MaxItems`), and a value with more is refused with `FCMS2103`, through the SDK and an import too; a declared maximum, higher or lower, holds instead (#3307).
- A content hook runs for at most `FluentCms:Content:HookTimeout` (30 seconds, a new option): one that runs longer has its token cancelled, and the write fails with the new code `FCMS2410` (503), naming the hook, and rolls back whole; it is logged with event 9406. A hook that ends after `FluentCms:Content:SlowHookThreshold` (1 second) is logged with event 9407. A scheduled publish or unpublish whose hook timed out is tried again (#3307).
- A line of a transfer package that names a locale for an entry of a type that is not localized is reported as an invalid item (`FCMS3212`) instead of an unexpected failure (`FCMS3215`) (#3305).
- A write that adds an entry to a site, or a locale of an entry, is refused with `FCMS2301` once the site is gone, also on an instance whose cache still has it, and a site deletion waits for such a write that is under way. `SiteDeletedEvent` is recorded in the outbox in the transaction of the deletion, so a cleanup of a plugin runs even when the process stops right after it (#3306).
- `IDataProvider.BeginSnapshotAsync` and `IDataProvider.LockSiteAsync` are new members with defaults: a provider other than the three of FluentCMS reads an export without a snapshot, and one whose database has more than one writer must lock the row of `cms_site` (#3305, #3306).

## Additions

- `POST /api/management/v1/transfer/import` takes `authors=keep|importer`, and `fluentcms import` takes `--authors keep|importer`: `importer` records the caller as the creator of the entries the import creates and as the updater of what it writes, where `keep`, the default, keeps the authors of the package (#3305).
- An export reads the entries of every type from one snapshot: a `REPEATABLE READ` transaction on PostgreSQL, a deferred transaction in WAL mode on SQLite, and `SNAPSHOT` isolation on SQL Server where the database allows it (`ALLOW_SNAPSHOT_ISOLATION ON`); without one it is logged with event 9189. It reads a batch of 100 entries in four queries (#3305).
- The lease of an `Idempotency-Key` is renewed every third of `InProgressTimeout` while its request runs, so a request that runs longer is not taken over and run again; a renewal that fails is logged with event 9144 (#3307).
