## Fixes

- A host that sets `Events` or `EventsType` on the options of a Google, Microsoft, GitHub or Apple provider of `FluentCms:Members:Providers` (`member-{name}`), or a delegate of `OnRemoteFailure` or `OnTicketReceived` in a `PostConfigure`, keeps FluentCMS's part of those two events: an error at the provider goes back to the member login page with a `member.login_failed` row, and the sign-in names the provider, so the external login page accepts it. FluentCMS's part runs first, then the host's. Before, the host's events replaced it, so such a provider's sign-ins were refused and its errors went to the error page (#3564).
