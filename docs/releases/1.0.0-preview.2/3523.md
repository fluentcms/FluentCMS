## Changes that break code built before this preview

- A request with an `Idempotency-Key` whose `FluentCms:Idempotency:Window` ends while it still runs keeps its key: a repeat answers 409 (`FCMS3142`) until it answers, and the retention job leaves the key, instead of claiming or removing it and letting the repeat run beside the request, which was then cancelled with `FCMS3142` and event 9145 as if the repeat had taken its key over (#3523).
- A request whose `Idempotency-Key` a repeat took over after its write committed, as while the entry was read back, answers what it wrote (201 with the entry, or the bulk result). It answered 409 (`FCMS3142`) with a message that said its write was rolled back. Its answer is not kept, since the key is the repeat's (#3523).

## Additions

- A request whose key passed its window and was removed after its lease ran out goes on, answers what it wrote, keeps nothing under the key, and is logged with the new event 9146; it is cancelled only once a repeat claims the key afresh (#3523).
