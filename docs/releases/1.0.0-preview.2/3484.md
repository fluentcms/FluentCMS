## Changes that break code built before this preview

- An SVG uploaded, replaced or imported from a package file with `Svg` set to `sanitize` loses every `<style>` element, whatever it holds, since a page that inlines the SVG would apply its rules to the whole page; `style` attributes stay. A drawing whose colours were in a `<style>`, as many editors export them, loses them (#3484).
- Every `id` of such an SVG, and every reference to one in `href`, `xlink:href`, `url(#…)`, `aria-labelledby`, `aria-describedby` and the `begin` and `end` of an animation, takes the prefix `fcms-`, eight hex digits of the SHA-256 of the file as uploaded and a hyphen, so that an inlined SVG puts no name on `window`, clashes with no id of the page or of another SVG and reaches no element of the page. A reference to no id of the file takes it too. A page or script that found an element of the SVG by its id finds it under the new one (#3484).
- Stored SVGs are not changed. An import line without a file that names the key of an SVG stored by an earlier build is refused with `FCMS3220`, since sanitising it now gives other bytes; a file of the package is sanitised and taken. Serve SVGs stored before this preview through the CMS, which sends them with its `Content-Security-Policy`, and do not inline them in a page or serve them through a CDN that drops that header (#3484).
