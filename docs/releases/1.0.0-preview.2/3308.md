## Changes that break code built before this preview

- On PostgreSQL the text columns of content fields that are not JSON have the collation `C`, so a sort on text, and the cursor that continues it, follow the code points, as on SQLite and SQL Server, and no longer the database's collation: `Banana` comes before `apple`, and `_cherry` no longer beside `cherry` (#3308). A query of PostgreSQL data that sorts on text, or pages through such a sort, returns another order than before. Nothing changes a content table at start. Changing a column keeps its type, rewrites no rows and rebuilds the indexes on the column, and its table is locked until that is done, so reads and writes of the type wait: do it in a maintenance window.
  - A host with content migrations runs `fluentcms migrations add` with a name of its own now, which with no schema change holds only an `AlterColumn` to `C` for each content text column, and then `fluentcms migrate`. Otherwise the alters wait for the host's next content migration and go in with it.
  - Schema apply does not compare collations, so the content tables that a host without content migrations already has keep the database's order; a column that schema apply adds, or whose type or nullability it changes, gets `C`. Recreate the database, exporting and importing the content, or run the statements that this query writes. They cover the `text` and `character varying` columns of the content tables, `cms_{type}` and `cms_{type}_i18n`, which alone have a `uuid` column `document_id` and a `smallint` column `state`, other than `locale`; system tables and `jsonb` columns are left out, and a column that has `C` already. Each statement keeps the column's own type: `TYPE text` on a `slug`, `url`, `email` or `select` column, or a text column with a maximum length, which are `character varying(n)`, leaves a type change that the next `fluentcms schema apply` refuses as destructive. Read the list before running it.

    ```sql
    SELECT format('ALTER TABLE %I ALTER COLUMN %I TYPE %s COLLATE "C";', c.table_name, c.column_name,
               CASE WHEN c.data_type = 'character varying' THEN format('character varying(%s)', c.character_maximum_length) ELSE c.data_type END)
    FROM information_schema.columns c
    WHERE c.table_schema = current_schema()
      AND c.data_type IN ('text', 'character varying')
      AND c.column_name <> 'locale'
      AND c.collation_name IS DISTINCT FROM 'C'
      AND EXISTS (SELECT 1 FROM information_schema.columns d WHERE d.table_schema = c.table_schema AND d.table_name = c.table_name AND d.column_name = 'document_id' AND d.data_type = 'uuid')
      AND EXISTS (SELECT 1 FROM information_schema.columns s WHERE s.table_schema = c.table_schema AND s.table_name = c.table_name AND s.column_name = 'state' AND s.data_type = 'smallint')
    ORDER BY c.table_name, c.ordinal_position;
    ```
