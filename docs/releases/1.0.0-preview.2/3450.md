## Additions

- `PATCH /me/preferences` changes the members its body names and keeps the others as they are stored, whatever the caller last read; null makes one no longer chosen. Two changes of different preferences sent at once, from two tabs or two devices, are both kept. `PUT /me/preferences` still replaces every value (#3450).
- `GET`, `PUT` and `PATCH /me/preferences` answer an `ETag`, a hash of the four values that changes with any of them. Both writes take it back as an optional `If-Match` and are refused with `FCMS3105` (412) once another write has changed the preferences; a malformed `If-Match` is `FCMS3131` (400). Without it they apply to whatever is stored, as before. The OpenAPI document describes the route, the header and the `ETag` (#3450).
