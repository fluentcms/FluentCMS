## Changes that break code built before this preview

- A save of a plugin's `PluginDbContext<T>` that adds a row with a `site_id` column, or moves a row to another site, holds the row of that site in `cms_site` until it commits, as a content write that adds an entry does, so a site's deletion waits for it and its row goes with the site's cleanup. A save for a site that is gone is refused with `FCMS2301` (`ValidationException`), also on an instance whose cache still has the site; it was saved and stayed as a row of a site that no longer exists. This covers the rows of the media, webhooks, MCP, multi-site, search and AI assist plugins, and a third-party plugin's. A media upload or import refused so deletes the file it wrote (#3485).
- For a plugin author: a `Guid` column `site_id` is always taken for a site, with no opt-out, so a value that is no site of FluentCMS is refused; a site in a value object, a member of a complex type or a column of another name is not guarded; `Update(entity)` marks every property modified and so takes the hold. A qualifying save now runs in a transaction, one of its own (up to three more round trips for a single insert) or the plugin's own, ambient or enlisted one, and `IEventBus.PublishAsync` while it is open is refused; a long transaction of the plugin keeps the site's deletion waiting (#3485).
- The default `IDataProvider.LockSiteAsync` reads `cms_site` by its name for a context whose model has no `Site`, such as a plugin's, and a third-party provider whose own `LockSiteAsync` reads `context.Set<Site>()` must do the same (#3485).
