## Additions

- The schema readers of PostgreSQL and SQLite list an index whose keys are expressions by its name, as the check behind `FCMS1308` and event 9306 finds the indexes of a model. On PostgreSQL an index of expressions alone, such as a GIN index on `to_tsvector`, was not listed, so a plugin whose model has one would be warned of it at every start, or refused for a unique one; on SQLite such a key failed the read. A key that is an expression is listed with an empty name. SQL Server indexes no expression, and an index on a computed column or with a filter was already listed (#3530).
- `fluentcms schema apply` and the schema sync of a development host leave alone an index on a content table that has an expression key and that the content model lacks, such as one made by hand on `lower(title)`, since the content model cannot declare one: apply does not drop it, and the sync does not report it with event 9303. On PostgreSQL an index of expressions alone was kept so before, since it was not listed, while one of columns and expressions was listed by its columns alone and dropped; on SQLite the read failed. An index of plain columns that the model lacks is dropped or reported as before (#3530).
