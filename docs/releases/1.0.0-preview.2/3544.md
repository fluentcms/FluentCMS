## Additions

- Disposing a handle of the database lock waits at most 5 seconds, as the job runner's disposal does, for the callbacks registered on its `Lost` token once the loss is being told. A callback that does not return kept the disposal waiting for it. When the bound is reached the disposal returns, after the release, and logs a warning with event 9168 (`LockLostCallbackSlow`); the callback runs on, the token stays usable until it returns, and what it throws then is logged with event 9167 as before (#3544).
