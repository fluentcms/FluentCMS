## Changes that break code built before this preview

- `fluentcms settings reprotect` ends with `FCMS3308` and exit code 1 when a stored settings document holds a protected value under a key its class does not read as a secret, such as one the class no longer has, that is not under the default key of the key ring; it is named by area, scope and key, never by value, and left as it is. Such a value was skipped without a word and the command ended with 0 (#3436).

## Additions

- `fluentcms settings reprotect` names the id of the default key of the key ring it protected under, so that the operator checks it is the key to keep before retiring another, and `--remove-area <area>` first removes the stored documents of an area no settings class of the host registers, such as that of a removed plugin; a registered area is refused with `FCMS3359`. The `settings-secrets-unprotected` line of the startup report names the command, and `docs/host-configuration.md` says when to run it while instances may still protect under an older key (#3436).
