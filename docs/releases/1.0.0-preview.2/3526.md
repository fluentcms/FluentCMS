## Changes that break code built before this preview

- A host that sets `Events` or `EventsType` on the `OpenIdConnectOptions` of an `Oidc` provider of `FluentCms:Members:Providers` (`member-{name}`) keeps FluentCMS's events of that provider: the login's key from the token's `sub`, the way back to the member login page after a failure, the provider's name in the ticket, and the remote sign-out and signed-out callback paths left unserved (404). FluentCMS's run first, then the host's, and an `EventsType` is resolved once a request as the handler would. Before, a host's events replaced them, so the handler answered the remote sign-out path itself (#3526).
- A host that replaces `Events` or sets `EventsType` on such a provider in a `PostConfigure` registered after `AddFluentCms` does not start, with `FCMS3180` naming the provider. A delegate of `options.Events` set there runs after FluentCMS's part of that event (#3526).
