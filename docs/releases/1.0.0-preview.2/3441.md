## Changes that break code built before this preview

- `IMcpClients.ListConsentsAsync` and `IMcpClients.EndConsentAsync` are new members with no default, which an implementation other than core's must add (#3441).
- A consent that would keep one MCP client more than `maxConsentsPerUser` ends on the hosted error page with `consent_limit_reached`, whose sentence tells the user to end a consent they no longer use or to ask an administrator. It ended there with `invalid_request` (#3441).

## Additions

- `GET /api/management/v1/mcp/consents` lists the MCP clients the `open` policy approved that count toward the caller's `maxConsentsPerUser`, each with `id`, `clientId`, `name`, `redirectUris`, `registeredAt`, `consentedAt` and `active`, a consent ended by its session or a password change included, and `DELETE /api/management/v1/mcp/consents/{id}` ends the caller's consent to one of them and frees its place. It deletes the caller's authorizations of the client with their tokens, so its access tokens stop at once, and the client no longer names the caller as `usedBy`; one that then holds no grant of anyone goes as a client never used, after `neverUsedClientHours`. Both need no permission and are the caller's own: a client that counts for another user, or for none, is `FCMS1603`, and a caller that is no user has none. The end of a valid consent is the activity row `user.sessions_ended` with the reason `revoked` (#3441).
- The consents that take a place run one at a time under the database lock `fluentcms:mcp-consents`, each counting what the others committed, so consents given at the same moment never pass `maxConsentsPerUser`. They passed it by as many as were in flight (#3441).
- `GET /api/management/v1/mcp/clients` answers `usedAt` and `usedBy` of each client, the time and the user of its first consent, and so do `McpClient.UsedAt` and `McpClient.UsedBy` (#3441).
- Event 9008 names the list of the user and the end of a consent: `Refused the consent of the user {UserId} to the MCP client {ClientId}: the user keeps {MaxConsentsPerUser} clients that the open policy approved already, as GET /api/management/v1/mcp/consents lists them to the user, some of them perhaps with a consent that was ended. The user frees one with DELETE /api/management/v1/mcp/consents/{id}; an administrator removes the clients not in use, or raises MaxConsentsPerUser.` (#3441).
