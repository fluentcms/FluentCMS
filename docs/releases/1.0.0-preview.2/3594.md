## Fixes

- `DELETE /api/management/v1/mcp/consents/{id}` revokes the caller's valid consents to the client with their tokens, and commits that, before it deletes them, so an MCP client that refreshes while its consent ends gets no token that works, and no refresh after the revoke passes. An end whose delete crosses a token issued under the consent still answers 409 with `FCMS1609` and frees no place, but the consent stays revoked and its tokens are refused, and the same call again frees the place. It rolled back whole, so a client that kept refreshing could make every end answer `FCMS1609` and keep the consent and its tokens. This corrects the note of #3441, which said such an end ends nothing (#3594).
