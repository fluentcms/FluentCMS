## Additions

- A package that maps endpoints of its own under a FluentCMS host, outside the groups of `MapFluentCms()`, does it with public members of `FluentCMS.Core` in `FluentCmsSurfaceExtensions`: `WithFluentCmsSurface(name)` makes them FluentCMS endpoints of that surface, with the security headers, the coarse rate limit, the request limits and the FluentCMS authentication, and refuses the names of core's surfaces; `WithContentSecurityPolicy(policy)` sets the policy of a page per request; `WithFluentCmsStaticFiles()` puts the files under `FluentCms:RateLimits:StaticFiles`; `EnsureFluentCmsPipeline(method)` stops the host with `FCMS1104` before `UseFluentCms()`; and `services.AddFluentCmsOptions(section, instance, validate)` binds `FluentCms:{section}` and stops the host with `FCMS1101` and the key, which `FluentCmsConfigurationException.InvalidOption(message)` raises from `validate`. `FluentCmsConfigurationException.NotRegistered(message)` raises `FCMS1103`, `PublicOrigin` is public with `Base` and `Issuer`, and `ClientOptions.FromOptionsProperty` names the property of a client that `cms.Clients` registered. `docs/host-configuration.md` has an example (#3451).
- `FluentCMS.Admin.Hosting` uses only those members, and Core no longer names it in `InternalsVisibleTo`, so a later patch of `FluentCMS.Core` that changes an internal member no longer breaks the admin's package at run time. The admin is served as before, with the same headers, limits and refusals at start (#3451).
- The admin marks the files of its app, their compressed copies and fingerprinted paths included, so they count under `FluentCms:RateLimits:StaticFiles` instead of `PreAuth`, and forty cold loads of the admin from one address a minute meet no 429. `index.html`, `config.json`, `/admin/`, the page of the client routes and every API request still count under `PreAuth` (#3577).
